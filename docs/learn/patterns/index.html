Как думает программа

30 паттернов: приёмы, из которых собраны приложения, игры и операционные системы. Один паттерн в день, у каждого код на Tachbit и задание.

Большая картина

Приложение, игра и ОС выглядят совсем разными, но внутри у них один скелет. Есть состояние (что программа помнит), события (что его меняет), цикл (кто ждёт события) и слои (кто за что отвечает). Разница только в том, как крутится цикл.

Приложение

ждать событие→разобрать→изменить состояние→перерисовать↺

Игра

dt→ввод→обновить мир→нарисовать кадр↺ 60 раз в секунду

Ядро ОС

прерывание→кто это→разбудить службу→выбрать следующую задачу↺

Неделя 1 · Основа логики
1СостояниеСначала выпишите, что программа помнит. Код — это правила, как это меняется.2ОхранникПлохие случаи проверяй первыми и выходи сразу. Хороший путь — последним, без вложенности.3НакопительИтог = начальное значение, затем один проход, каждый элемент меняет итог.4Фильтр → преобразование → свёрткаОтбери, измени каждый, сверни в одно. Каждый шаг — отдельный цикл.5МодельКаждая вещь из задачи — свой тип. Поля — только то, что действительно нужно помнить.6Чистая функцияВсё нужное — в параметрах, результат — через return, ничего вокруг не меняется.7Ошибка как значениеКто не знает, что делать, — передаёт дальше. Кто знает — обрабатывает.
Неделя 2 · Как устроены приложения
8СправочникЕсли ищешь по ключу чаще одного раза — нужен словарь, а не перебор.9Загрузить → изменить → сохранитьНет файла — начни с пустого. Ошибку записи никогда не молчи.10СлоиНижний слой не знает о верхнем. Вывод только читает, логика только считает.11Цикл событийЖди → разбери → ответь → снова жди. Внутри круга только быстрые дела.12Модель / видСобытия меняют модель. Рисование только читает модель.13Конечный автоматОдин enum на режим, одна функция переходов. Никаких пар флажков.14КомандаДействие — это объект. История — список команд. Отмена — обратная команда.
Неделя 3 · Как устроены игры
15Игровой циклКаждый кадр: dt → ввод → обновить → нарисовать. Скорость всегда × dt.16Интеграторскорость += ускорение × dt; позиция += скорость × dt.17Пересечение коробокНе пересекаются, если одна целиком с одной стороны. Иначе — касание.18Список сущностейОбновить всех → собрать живых в новый список → заменить.19Автомат экрановРежим программы — один enum. Каждый экран обрабатывает только свои события.20Плавный переходЗначение = lerp(было, стало, ease(t)). t идёт от 0 до 1 по времени.21Очередь событийИсточник только сообщает. Слушатели сами решают, что делать.22Смотри → реши → действуйПравила от срочного к обычному. Первое подходящее и выигрывает.
Неделя 4 · Как устроена система
23СлужбаСвои данные у каждого. Просьба — сообщение в канал. Ответ — сообщение обратно.24ВладениеУ каждого куска один хозяин. Взял — отдай ровно один раз.25Раздели и собериКаждый работник — своя часть. Общее — shared и только под lock.26Производитель / потребительМежду ними канал. Закрыл канал — значит работы больше нет.27КольцоФиксированный массив, два указателя, всё по модулю длины.28По кругуОчередь задач. Каждой — квант. Не закончила — в конец очереди.29Проверка на входеПраво проверяет тот, кто выполняет действие, а не тот, кто показывает кнопку.30Состояние + события + цикл + слоиЛюбую программу можно разложить на эти четыре части.
Главная мысль курса. Перед кодом ответьте на четыре вопроса. Что программа помнит? Какие события её меняют? Какой у неё цикл? На какие слои она делится? Если ответы есть, код пишется почти сам.
