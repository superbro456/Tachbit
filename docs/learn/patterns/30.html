Посмотрите назад: у калькулятора, футбола и операционной системы один скелет. Есть состояние (модель, часто с режимом-автоматом). Есть события, которые его меняют. Есть цикл, который события ждёт или крутится по кадрам. И есть слои: вывод только читает, логика только считает, хранение только хранит.

Когда вы открываете чужой код, ищите эти четыре вещи. Когда пишете свой — начинайте с них: какие режимы, какие события, какой цикл, какие слои. Дальше остаётся заполнить функции.

Паттерн «Состояние + события + цикл + слои»

Любую программу можно разложить на эти четыре части.

ПриложениеСписок дел: модель задач, клики, цикл окна, слой сохранения.
ИграФутбол: мир и счёт, ввод и голы, игровой цикл, физика отдельно от рисования.
ОСOmnium: клетки и службы, прерывания и сообщения, цикл ядра, драйверы → ФС → оболочка.

Код

day30.tb
// день 30: общий скелет — состояние, события, цикл, слои
enum Mode
    work
    done

obj App
    mode: Mode
    todo: list text

func handle(a: App, ev: text)            // события меняют состояние
    if ev == "готово" and len(a.todo) > 0
        last = a.todo.pop()
    if len(a.todo) == 0
        a.mode = Mode.done

func draw(a: App)                        // вывод только читает
    print("режим:", a.mode, " дел:", len(a.todo))

func main()
    a = App(mode: Mode.work, todo: ["код", "тест", "отправить"])
    each ev in ["готово", "готово", "готово"]   // цикл событий
        handle(a, ev)
        draw(a)
Вывод
режим: work  дел: 2
режим: work  дел: 1
режим: done  дел: 0
