# Омниум на Tachbit

Омниум пишется заново на Tachbit. Всё ядро — программа `tb bare`: 64 бита (x86-64), собирается
только через LLVM, C компилятор не пишет. Библиотека ядра (`omnium/kernel/`) — как libc у C:
готовый слой под языком (переключение задач, прерывания, страницы, загрузка).

Идея та же, что в «галактическом ядре» (OmniumOS #2–#7): все программы в одном адресном
пространстве, друг до друга дотягиваются только через каналы, память защищает язык, а не процессор.

## Где что лежит

Всё, что относится к ОС, — в этой папке:

| Папка, файл | Что |
|---|---|
| `kernel/kernel.h` | библиотека ядра: загрузка (multiboot → 64 бита), своя маленькая libc, память и квоты клеток, прерывания, задачи и планировщик, страницы памяти, несколько ядер процессора |
| `kernel/screen.h` | экран (видеокарта QEMU/Bochs, буфер кадра) и мышь (PS/2, vmmouse) |
| `kernel/elf_link.py` | свой компоновщик ядра: `.o` → `.elf` для загрузчика |
| `console.tb`, `clock.tb`, `keyboard.tb` | службы Омниума на Tachbit |
| `rtc.tb` | драйвер часов реального времени (CMOS): служба «время» |
| `shell.tb` | оболочка «Капля»: окна из матового стекла, капсула, поиск, приложения Терминал, Заметки, О системе, Часы |
| `fonts/` | шрифт Inter (лицензия OFL, `fonts/OFL.txt`): ядро берёт его с собой при сборке |
| `ofs.tb` | файловая служба OFS3: файлы с версиями, контрольные суммы, удаление, снимки, ключи «читать / писать», отзыв ключа |
| `ofs_test.tb` | проверка OFS3 (идёт в `./tests/run_bare.sh`) |
| `desktop.tb` | ядро с оболочкой: службы, клетки, журнал → Терминал (`./omnium/run.sh`) |
| `main.tb` | первый пример без экрана: службы и клетки в терминале (`./omnium/run.sh --text`) |
| `run.sh` | собрать и запустить в QEMU |

Компилятор берёт `kernel/*.h` при сборке (`tools/embed_runtime.py` вставляет их в `compiler/runtime.h`
на места строк `//@include`), поэтому после правки в `kernel/` нужно `python3 tools/embed_runtime.py` и `./tools/build_tb.sh`.

## Слова Омниума и что им соответствует в Tachbit

| Омниум | Tachbit | Где живёт |
|---|---|---|
| звезда (диспетчер на ядре процессора) | планировщик задач | библиотека ядра |
| клетка (программа) | `background f(...)` | код Омниума |
| служба | `service f(...)`: как background, но ей оставлен запас памяти (последние 8 МБ кучи) | язык + ядро |
| канал | `channel T`, `.send`, `.receive` | язык |
| перенос без копии | `move` | язык |
| ключ (право на службу) | конец канала: у кого канал — у того право | код Омниума |
| драйвер (доверенная орбита) | модуль, где можно `danger` | компилятор проверяет |
| обычная программа | модуль без `danger` | компилятор проверяет |
| прерывание → событие | `func f() on timer / on keyboard / on interrupt N` | язык |
| пояс Койпера (чужой C) | отдельное пространство страниц, кольцо 3 | позже |

Системных вызовов нет. Программа пишет в канал службы, служба отвечает в свой канал.

## Слои

1. **Звёзды.** Один планировщик на каждое ядро процессора. Клетка живёт на одной звезде,
   звёзды забирают работу друг у друга, когда у соседа очередь длиннее.
2. **Клетки.** Свой стек, своя куча с квотой. Падение клетки (деление на ноль, выход за список,
   нехватка квоты) заканчивает только её; тот, кто её запустил, узнаёт об этом из `a.crashed`.
3. **Каналы и ключи.** Клетка получает при запуске только нужные каналы. Других служб она не видит:
   адрес службы взять неоткуда, язык не даёт сделать указатель из числа вне `danger`.
4. **Службы.** Консоль (экран + COM1), часы, клавиатура, память (страницы для драйверов),
   позже диск, файлы, сеть, экран для оболочки.
5. **Орбиты доверия.** Драйверы — модули с `danger` (порты, адреса). Программы — без `danger`,
   это проверяет компилятор при сборке. Подпись кода — позже.
6. **Оболочка.** Своя библиотека разметки и стилей на Tachbit (на основе `lib/ui.tb`), рисует GPU.

## Память (из старой Омниум)

- У каждого куска памяти есть хозяин — клетка. Что уходит из клетки (аргументы `background`,
  текст в канале, список через `move`), становится ничьим, а взявший из канала становится хозяином.
- Упала клетка — ядро проходит кучу и возвращает все куски с её меткой: двенадцать клеток по 12 МБ
  подряд падают в куче 64 МБ, и места хватает.
- Квота клетки — 16 МБ. Последние 8 МБ кучи — запас: туда могут только ядро, прерывания и службы
  (`a = service f()`). Обычная клетка, упёршаяся в запас, падает одна; службы работают дальше.
- `new_mem` / `grow_mem` не роняют клетку, когда памяти нет: отвечают ошибкой (`else err`).

## Файлы: OFS3 (`ofs.tb`)

Служба в своей клетке, ходит только по каналам. Ключ — пара каналов; у кого ключ, тот и ходит к файлам.

```
use ofs
bell = channel int
asks = list channel text
answers = list channel text
writes = list bool
k = ofs.key(bell, asks, answers, writes, true)     // читать и писать
r = ofs.key(bell, asks, answers, writes, false)    // только читать
fs = service ofs.ofs(bell, move asks, move answers, move writes)
v = ofs.put(k, "заметки", "купить хлеб") or 0      // номер версии
s = ofs.get(r, "заметки") or ""
old = ofs.get_version(k, "заметки", 1) or ""
ofs.snapshot(k, "утро") ...  ofs.restore(k, "утро") ...   // возврат — тоже новые версии
ofs.revoke(k, r) ...                                       // у r дальше «ключ отозван»
bell.close()
```

Каждое чтение сверяет контрольную сумму версии; `ofs.check(k)` проверяет все. Ключи раздают до
запуска службы. Пока файлы в памяти; диск (virtio) встанет под эту же службу.

Сборка и запуск: `./omnium/run.sh` — окно QEMU с оболочкой. Печатай или жми лупу в капсуле — откроется поиск (имена
приложений можно и латиницей: terminal, notes, about, clock), Enter открывает первое; окна таскают за ушко.
Если мышь в окне QEMU «залипла», Ctrl+Alt+G (на Mac Ctrl+Option+G) отпускает её. Нужны clang и QEMU (на Mac: `xcode-select --install` и `brew install qemu`); если есть инструменты LLVM (opt, llc, llvm-link), берутся они.
